The Engineering Challenge

🌲

The Degeneration Problem

An interval tree is conceptually a standard Binary Search Tree ordered by interval start times. However, if intervals are inserted in sorted order (adversarial insertion), a naive BST degenerates into a right-leaning linked list. A query would then take O(N) instead of O(log N). AVL balancing guarantees the height remains tight, but introduces a new problem: Rotations.

🔄

The Rotation Repair Rule

Interval queries rely on a `max` field at each node, representing the maximum end time anywhere in its subtree. When an AVL rotation shifts subtrees between nodes to restore height balance, the subtree structures change! This means the `max` field of the rotated nodes is instantly invalidated and MUST be recomputed bottom-up immediately after the rotation.

☠️

The Silent Corruption

Toggle the "Sabotage Controls" on, and the rotation code will skip updating the `max` fields. The tree will still perfectly balance its height, but its augmented data will be stale. When you run an Overlap Query, the algorithm uses the `max` field to prune branches. Because the field is wrong, it will incorrectly prune valid branches, returning incomplete results! The visualization explicitly proves this bug.
