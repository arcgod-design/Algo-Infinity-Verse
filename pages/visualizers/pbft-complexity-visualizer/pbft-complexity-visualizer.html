The 3f+1 Byzantine Threshold

In crash-fault systems like Raft, tolerating f dead nodes requires 2f+1 total nodes. But Byzantine nodes actively lie and send conflicting information. To defeat this, PBFT requires 3f+1 total nodes. If you set N=4, you can only tolerate f=1 Byzantine node. If you set F=2 when N=4, consensus will intentionally fail!

💥

Why O(n²) Messages?

Because nodes might lie about what the Primary leader told them, every backup node must verify the request with every other backup node (the Prepare phase). Then, to guarantee that a quorum has agreed to execute, they must tell every other backup node that they are committing (the Commit phase). This causes a quadratic explosion in network traffic.

🚀

Raft Comparison

Raft inherently assumes all nodes are honest. The Leader simply broadcasts an AppendEntries RPC to everyone (O(n)), and they reply to the Leader (O(n)). There is zero peer-to-peer cross-communication. This makes Raft lightning fast, but utterly defenseless if a node gets hacked or turns malicious.
