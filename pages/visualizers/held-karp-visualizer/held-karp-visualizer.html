Held-Karp Algorithm

The Bitmask DP That Makes TSP "Only" Exponential

The Traveling Salesperson Problem (TSP) is famously NP-Hard. A naive brute-force search checks every possible permutation, resulting in a devastating O(n!) factorial complexity. The Held-Karp algorithm uses Bitmask Dynamic Programming to remember subpaths, dropping the complexity to O(n² · 2ⁿ). It doesn't make TSP magically fast for massive graphs, but the astronomical difference between factorial and exponential growth is a landmark lesson in algorithmic limits.

The "Still Exponential" Truth

🤯

The Factorial Nightmare

Brute force TSP requires checking every permutation of cities to find the shortest loop. For N cities, that's (N-1)! / 2 paths. Factorial growth is uniquely terrifying. At N=12, it's 20 million operations. At N=20, it's 60 quadrillion operations. The universe will end before a standard computer solves N=25 via brute force.

🧠

The DP Bitmask Solution

Held and Karp realized that if you're evaluating paths, the specific order of the cities in the middle of a route doesn't matter for future decisions—only which cities you've visited and where you currently are. By using a binary bitmask (e.g., 1011 means cities 0, 1, and 3 are visited) to memorize the shortest path to every sub-state, redundant work is completely eliminated.

🚧

The Honesty Panel: The 25-City Wall

Held-Karp reduces the complexity to O(N²·2ᴺ). Is it fast? Compared to factorial, it's a miracle (N=15 takes seconds instead of centuries). However, it is still strictly exponential. Because the algorithm must store N·2ᴺ states in memory, it rapidly consumes gigabytes of RAM. In practice, exact Held-Karp hits a hard wall around N=20-25. It does not "solve" TSP for massive maps—it just buys us a bounded, numerical improvement.
