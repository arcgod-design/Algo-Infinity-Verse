Primality Testing

Probabilistic Speed vs Deterministic Certainty

Modern cryptography (RSA, ECC, PQC) relies entirely on discovering massive prime numbers. But how do we know a 1024-bit number is prime? The Miller-Rabin test is lightning fast but uses probability, risking a tiny chance of a false positive. The AKS Algorithm provides absolute mathematical certainty, but is far too slow for cryptographic use. Watch the tradeoff live.

AKS Algorithm Reference

Deterministic Polynomial

The AKS primality test relies on the polynomial congruence:

(X + a)ⁿ ≡ Xⁿ + a (mod n)

If this holds for a specific range of a, n is absolutely guaranteed to be prime. No false positives.

Note: AKS runs in O(log⁶ n), which is theoretically polynomial but practically far too slow for 2048-bit RSA keys compared to Miller-Rabin's O(k log³ n).

Theoretical Deep Dive

🎭

The Carmichael Trap (False Positives)

Try testing 341 with witness a = 2. Miller-Rabin will declare it "Probably Prime". But 341 = 11 × 31, making it a composite! 341 is a Fermat pseudoprime to base 2. This is exactly what "probabilistic" means. But test it again with witness a = 3, and the illusion shatters—it correctly flags as composite. This is why cryptography runs 40+ random rounds of testing.

📉

Probability Shrinking

If a number is composite, at least 3/4 of all possible witnesses a will correctly expose it. Thus, the probability of a composite surviving k random rounds is at most (1/4)^k. After just 40 rounds, the chance of a false positive is less than 1 in 1,208,925,819,614,629,174,706,176. That is absolute cryptographic certainty.

✨

The 2002 Breakthrough (AKS)

For centuries, it was unknown if a deterministic algorithm could prove primality in polynomial time. In 2002, Agrawal, Kayal, and Saxena proved it was possible. While a massive theoretical leap, the high constant factors in its O(log⁶ n) runtime mean OpenSSL and TLS still use Miller-Rabin to generate your secure encryption keys today.
