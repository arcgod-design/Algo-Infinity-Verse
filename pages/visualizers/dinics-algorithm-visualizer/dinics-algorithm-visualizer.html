Dinic's Algorithm

The Elegance of Simultaneous Shortest Paths

While Ford-Fulkerson / Edmonds-Karp pushes flow one path at a time, Dinic's Algorithm brilliantly splits the work into phases. First, a BFS builds a Level Graph. Then, a DFS finds a Blocking Flow through all shortest paths simultaneously using Pointer Advancement to never re-traverse dead ends. The result? A massive theoretical jump to O(V²E).

Theoretical Deep Dive

🔍

BFS: The Level Graph

Instead of finding any path, Dinic's performs a BFS from the source in the residual graph to assign a shortest-path distance (level) to every node. Only edges that go strictly from Level L to Level L+1 are kept. This prevents the DFS from ever wandering backward or sideways, heavily pruning the search space.

🌊

DFS: The Blocking Flow

Once the level graph is built, we use DFS to send flow. But we don't just find one path and stop! We keep running DFS to find paths until the sink is unreachable in the current level graph. This saturated state is called a Blocking Flow.

✂️

Pointer Advancement

The true magic of Dinic's is Pointer Advancement. If the DFS discovers an edge is fully saturated, or that it leads to a dead end where no more flow can reach the sink, it permanently crosses that edge off for the rest of the phase. It is never checked again, ensuring O(VE) time per phase.

⏱️

O(V²E) Complexity

Because the shortest path distance from Source to Sink strictly increases after every blocking flow phase, there can be at most V phases. Each phase takes at most O(VE) time thanks to pointer advancement, resulting in the brilliant overall bound of O(V²E).
