01

Introduction to Dart

Dart is a client-optimized, object-oriented programming language developed by Google and first released in 2011. It is the language behind Flutter, Google's UI toolkit for building natively compiled apps for mobile, web, and desktop from a single codebase.

Dart is compiled with AOT (ahead-of-time) compilation to fast, predictable native machine code, and supports JIT (just-in-time) compilation with a hot-reload development loop. Its type system is sound — your code runs with type safety baked in.

Why Learn Dart?

  • Everything is an object: Even numbers and functions are objects, giving you a consistent, powerful model.
  • Sound null safety: The type system eliminates null reference errors at compile time.
  • Fast development: JIT + hot reload makes Flutter's iterative workflow lightning fast.
  • Great for UI: Declarative widget trees and reactive state management feel natural in Dart.
  • Runs anywhere: Mobile (Flutter), web (dart2js), desktop, and server-side (dart:io).
Dart 
// Hello, World!
void main() {
  print("Hello, Dart!");
  print("Fast. Productive. Everywhere.");
}

02

Variables & Data Types

Dart offers several ways to declare variables: var for type inference, final for single-assignment values, and const for compile-time constants. You can also annotate types explicitly for clarity.

var vs final vs const

  • var — Type inferred at declaration. The variable can be reassigned later.
  • final — A value set once at runtime. Cannot be reassigned after initialization.
  • const — A compile-time constant. Must be computable before the program runs.
Dart 
// Type inference with var
var name = "Alice";           // inferred as String
var score = 95;               // inferred as int

// Explicit types
String greeting = "Hello";
int year = 2026;
double pi = 3.14159;
bool isActive = true;

// final: assigned once at runtime
final int timestamp = DateTime.now().millisecondsSinceEpoch;

// const: compile-time constant
const double gravity = 9.8;

// String interpolation
final message = "User: $name, Score: ${score + 5}";
print(message);               // User: Alice, Score: 100
Output
User: Alice, Score: 100

Prefer final by default and reserve var for variables that genuinely change. Use const whenever a value can be computed at compile time — it improves performance and prevents accidental mutation.

Control Flow

Dart's control flow will feel familiar — if/else, switch, and all the standard loops — with a few modern conveniences like collection if and pattern-matching switch statements.

Dart 
void main() {
  final score = 85;

  // if / else if / else
  final grade = score >= 90
      ? "A"
      : score >= 80 ? "B" : "C";
  print("Grade: $grade");

  // switch statement
  switch (grade) {
    case "A":
      print("Excellent!");
      break;
    case "B":
      print("Good job!");
      break;
    default:
      print("Keep practicing.");
  }

  // for loop with ranges
  for (var i = 1; i <= 3; i++) {
    print("Count: $i");
  }

  // for-in over a collection
  for (final lang in ["Dart", "Flutter", "Firebase"]) {
    print(lang);
  }

  // while loop
  var x = 3;
  while (x > 0) {
    print(x);
    x--;
  }
}

Modern Switch Patterns

  • Pattern matching: Newer Dart switch statements can match object shapes, e.g. case [1, 2]:.
  • Logical-or patterns: case "A" || "B": combines cases without falling through.
  • Switch expressions: final s = switch (grade) { "A" => "Top", _ => "Other" }; returns a value directly.

Null Safety

Dart has sound null safety — the type system makes non-nullable types the default. A variable of type String can never hold null; you must opt in to nullability with ?. This eliminates entire classes of bugs at compile time.

Nullable vs Non-Nullable

  • Non-nullable: String name — guaranteed to hold a String. Safe to use directly.
  • Nullable: String? name — may hold null. Must be handled before use.
Dart 
void main() {
  // Non-nullable: cannot hold null
  String nonNullable = "Hello";
  // nonNullable = null;  // Compile error!

  // Nullable type
  String? nullable = "World";
  nullable = null;  // OK

  // 1. Safe call operator (?.)
  final length = nullable?.length;  // null if nullable is null

  // 2. Null-aware operator (??)
  final result = nullable ?? "Default value";

  // 3. Null-aware assignment (??=)
  String? label;
  label ??= "assigned";  // only assigns if label is null

  // 4. Bang operator (!) -- assert non-null
  // final forced = nullable!.length;  // Throws if null!

  // 5. late: lazily initialized non-nullable
  late String greeting;
  greeting = "Hi there";
  print(greeting);

  // Practical example
  String? fetchUserName(int id) => id == 1 ? "Alice" : null;
  final name = fetchUserName(5) ?? "Unknown";
  print(name);  // Unknown
}

Avoid the ! operator in production code — it re-introduces the risk of a null error. Prefer ?., ??, and pattern matching to handle nulls idiomatically and safely.

Practice: Null Safety

What does the null-aware operator ?? do in Dart?

  1. Throws an exception if the left side is null
  2. Returns the left side if non-null, otherwise evaluates the right side
  3. Converts a nullable type to a non-nullable type
  4. Declares a late variable

Correct Answer: B

The ?? operator returns the left-hand value when it is non-null; otherwise it evaluates and returns the right-hand expression. It is the idiomatic Dart way to supply defaults for nullable values.

05

Functions

Functions in Dart are first-class citizens — you can assign them to variables, pass them as arguments, and return them from other functions. Dart supports required parameters, optional positional parameters, named parameters, and concise arrow syntax.

Dart 
// Standard function
String greet(String name) {
  return "Hello, $name!";
}

// Arrow function (single expression)
int doubleIt(int x) => x * 2;

// Optional positional parameter [brackets]
String describe(String name, [int? age]) =>
    age == null ? name : "$name is $age years old";

// Named parameters {braces} with defaults
void createUser(String name, {int age = 18, String role = "user"}) {
  print("$name ($age) - $role");
}

// Higher-order function
int operate(int a, int b, int Function(int, int) op) => op(a, b);

// Anonymous function (lambda)
final sum = (int a, int b) => a + b;

void main() {
  print(greet("Alice"));
  print(doubleIt(21));

  print(describe("Bob"));
  print(describe("Bob", 30));

  createUser("Charlie", age: 25, role: "admin");

  final nums = [1, 2, 3, 4, 5];
  final evens = nums.where((n) => n.isEven).toList();
  print(evens);  // [2, 4]

  print(operate(10, 5, (a, b) => a - b));  // 5
}
Output
Hello, Alice!
42
Bob
Bob is 30 years old
Charlie (25) - admin
[2, 4]
5

Named parameters make call sites self-documenting — createUser(age: 25, name: "Bob") reads like a sentence. They also let you omit arguments without breaking callers.

Practice: Functions

What is the result of final f = (int n) => n * n; f(6)?

  1. 6
  2. 36
  3. 12
  4. 66

Correct Answer: B

f is an anonymous arrow function that squares its argument. f(6) returns 36. Functions can be stored in variables and used like any other value in Dart.

Classes & Mixins

Dart is fully object-oriented. Classes support constructors (including named constructors), getters/setters, inheritance via extends, abstract classes, and — uniquely — mixins with the with keyword to reuse code across unrelated classes.

Dart 
// Class with a generative constructor
class User {
  final int id;
  final String name;

  User(this.id, this.name);  // shorthand constructor

  String describe() => "User #$id: $name";
}

// Named constructor
class Point {
  final double x;
  final double y;

  Point(this.x, this.y);

  Point.origin() : x = 0, y = 0;

  double get magnitude => x * x + y * y;
}

// Inheritance with abstract class
abstract class Animal {
  final String name;
  Animal(this.name);
  void speak();
}

class Dog extends Animal {
  Dog(super.name);
  @override
  void speak() => print("$name barks!");
}

// Mixin: reusable behavior without inheritance
mixin Swimmer {
  void swim() => print("Swimming!");
}

class Duck extends Animal with Swimmer {
  Duck(super.name);
  @override
  void speak() => print("$name quacks!");
}

void main() {
  final user = User(1, "Alice");
  print(user.describe());

  final p = Point.origin();
  print(p.magnitude);  // 0.0

  final duck = Duck("Daffy");
  duck.speak();   // Daffy quacks!
  duck.swim();    // Swimming!  (from mixin)
}
Output
User #1: Alice
0.0
Daffy quacks!
Swimming!

Mixins vs Inheritance

  • extends — a single inheritance chain. Use for "is-a" relationships.
  • with (mixin) — reuse behavior across unrelated classes. Use for "has-a" capabilities like Swimmer, Comparable, or logging.
  • implements — treat a class as an interface and provide your own implementation.
Practice: Classes & Mixins

What keyword adds a mixin's behavior to a class?

  1. extends
  2. with
  3. implements
  4. @mixin

Correct Answer: B

Mixins are applied with the with keyword: class Duck extends Animal with Swimmer. A class can apply multiple mixins: with Swimmer, Flyer. Unlike inheritance, mixins don't create a parent-child relationship.

07

Collections

Dart ships with rich collections — List, Set, and Map — plus collection if, spread operators, and a powerful set of functional methods for transforming data.

Dart 
void main() {
  // List (ordered, indexable)
  final fruits = ["Apple", "Banana", "Cherry"];
  print(fruits[1]);  // Banana
  fruits.add("Date");

  // Set (unique elements)
  final unique = {1, 2, 2, 3};
  print(unique);  // {1, 2, 3}

  // Map (key-value pairs)
  final userMap = {
    "name": "Alice",
    "age": 30,
  };
  print(userMap["name"]);

  // Collection-if
  final isAdmin = true;
  final roles = ["user", if (isAdmin) "admin"];
  print(roles);  // [user, admin]

  // Spread operator
  final more = [0, ...fruits];
  print(more.length);  // 5

  // Functional operations
  final numbers = [1, 2, 3, 4, 5, 6];
  final evenSquares = numbers
      .where((n) => n.isEven)
      .map((n) => n * n)
      .toList();
  print(evenSquares);  // [4, 16, 36]

  final total = numbers.reduce((a, b) => a + b);
  print(total);  // 21
}
Output
Banana
{1, 2, 3}
Alice
[user, admin]
5
[4, 16, 36]
21

Common Collection Methods

  • map — transform each element into a new value
  • where — filter elements by a predicate
  • reduce / fold — combine elements into a single value
  • any / every — check predicates across the collection
  • firstWhere — find the first element matching a predicate
Practice: Collections

What does {1, 2, 2, 3} evaluate to in Dart?

  1. [1, 2, 2, 3]
  2. {1, 2, 3}
  3. {1: 2, 2: 3}
  4. A compile error

Correct Answer: B

Curly braces create a Set, which stores only unique elements. The duplicate 2 is dropped, leaving {1, 2, 3}.

Async/Await & Streams

Dart handles asynchronous work with Future (a single value later) and Stream (a sequence of values over time). The async/await syntax keeps async code readable and linear, while async* generators make streams effortless.

Dart 
import "dart:async";

// A Future: one value later
Future<String> fetchUserData(int id) async {
  await Future.delayed(const Duration(milliseconds: 300));
  return "User data for #$id";
}

// A Stream: many values over time
Stream<int> countDown(int from) async* {
  for (var i = from; i > 0; i--) {
    await Future.delayed(const Duration(milliseconds: 200));
    yield i;
  }
}

void main() async {
  // await: pause until the Future completes
  final data = await fetchUserData(1);
  print(data);

  // await for: listen to each stream event
  await for (final n in countDown(3)) {
    print("Tick: $n");
  }

  // listen: subscribe with callbacks
  final controller = StreamController<String>();
  controller.stream.listen((msg) => print("Got: $msg"));
  controller.add("Hello");
  controller.add("World");
  await controller.close();

  // Handling errors on a Future
  try {
    await Future.error("boom");
  } catch (e) {
    print("Caught: $e");
  }
}
Output
User data for #1
Tick: 3
Tick: 2
Tick: 1
Got: Hello
Got: World
Caught: boom

Future vs Stream

  • Future<T> — completes once with a value (or error). Use await or .then().
  • Stream<T> — emits zero or more values over time. Use await for, .listen(), or stream transformers like .map() and .where().
  • async* — marks a function as a stream generator that emits values with yield.
Practice: Async/Await & Streams

Which keyword generates a Stream from a function that yields multiple values?

  1. async
  2. async*
  3. await
  4. yield*

Correct Answer: B

An async* function returns a Stream and emits values using yield. A plain async function returns a Future — a single value. yield* delegates to another stream.

09

Dart & Flutter

Flutter is written in, powered by, and extended through Dart. Everything you have learned — null safety, classes, mixins, collections, and async/await — is the foundation of every Flutter app. Dart's AOT compilation gives Flutter its native performance, while JIT + hot reload powers its fast development loop.

How Dart Powers Flutter

  • Single codebase: One Dart codebase compiles to native code for iOS, Android, web, and desktop.
  • Widgets as functions: UI is built by composing widget classes — Flutter's tree is just Dart objects.
  • Reactive state: setState, FutureBuilder, and StreamBuilder react to data changes automatically.
  • Sound null safety: Eliminates crashes from missing widget/state values before shipping.
  • No bridge overhead: Dart compiles to native machine code — no JavaScript bridge slowing things down.
Dart — Flutter Widget 
import "package:flutter/material.dart";

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: const Text("Dart & Flutter")),
        body: const Center(child: CounterView()),
      ),
    );
  }
}

// Stateful widget with setState
class CounterView extends StatefulWidget {
  const CounterView({super.key});

  @override
  State<CounterView> createState() => _CounterViewState();
}

class _CounterViewState extends State<CounterView> {
  int _count = 0;

  void _increment() {
    setState(() => _count++);
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      mainAxisSize: MainAxisSize.min,
      children: [
        Text("Count: $_count"),
        FilledButton(
          onPressed: _increment,
          child: const Text("Increment"),
        ),
      ],
    );
  }
}

Stateless vs Stateful: Use StatelessWidget when the UI never changes on its own. Use StatefulWidget when the widget holds mutable state — setState marks the widget dirty and triggers a rebuild. For async data, prefer FutureBuilder and StreamBuilder, which tie directly into the Dart futures and streams from Lesson 8.
